# 画面設計仕様 — 音声同期プレーヤー

策定日: 2026-11-09  
対象: Android版「音声同期プレーヤー」  
実装基準: 0.3.0-dev  
設計対象: 同一録音のローカル自動同期・手動時間補正・詳細診断を行う、単一画面のユーザーインターフェース

この文書は、旧画面からの変更箇所を列挙する差分ではない。画面の構成、言葉の意味、状態遷移、寸法、動作条件、検証条件を独立して定義した設計仕様である。音声照合のアルゴリズムと自動シークの回数は変更しない。

## 1. 使用目的と基本原則

外部機器で再生される音をスマートフォンのマイクで取得し、端末内にある同一録音の再生位置を推定して、イヤホン側の音を合わせる。ユーザーが通常行う操作は、音源選択・「同期を開始」・再生中の時間補正である。手動の「再生」は、音源の確認などの補助操作であり、同期開始の代わりではない。

- 操作に必要な状態とボタンだけを通常画面に置き、技術的な情報は詳細表示で見る。
- ボタンの意味を繰り返す説明（「左は遅らせる」「選択中の音源」「手動再生」など）は置かない。
- 無理なカタカナ表現や演出的な文章を使わない。
- レイアウトは再生・同期の状態によって飛び移らない。表示内容だけを更新する。
- マイク入力・認識・ローカル再生は別の状態として扱う。ローカルの再生はマイク停止後も続く。
- 同一録音の自動同期は初回に一度だけ再生位置を移動する。以後の照合は自動シークしない。

## 2. 表示用語と量の定義

### 2.1 「同期オフセット」

**主表示名は「同期オフセット」**とする。スライダー横に符号付き値を `同期オフセット +250 ms` のように表示する。

これはユーザーが設定する、**次の初回自動同期時のローカル再生位置への時間的な加算量**である。初期値0 ms、範囲−600〜＋600 ms、10 ms刻み。正ならローカルを先に進め、負なら後ろへ戻す。スライダーを操作しても、その時点で流れている音源をシークしない。

「バイアス」は意味が広く、「遅延」は実際のイヤホン遅延を測った量と誤認されるため、主表示には使わない。「初回補正」は機能を説明する言葉だが、独立した設定名としては使わない。

詳細設定には短い補足として「次の同期開始時に適用。＋はスマホ側を進める」を表示してよい。通常画面には長文説明を置かない。

### 2.2 「補正」

プレーヤーの `−100`, `−50`, `+50`, `+100` ボタンは、再生中の**手動時間補正の要求**である。下部には正味の要求量を、`補正 +150 ms` のように表示する。

ここでの値は各ボタンで*受け付けた補正要求の符号付き合計*。0.95倍または1.05倍で補正している間も値は変化させない。実際に音響出力へ反映された時間差、未処理の残り時間、プレーヤーの再生時刻を意味しない。

数値は受け付けたボタン操作時のみ更新する。音源の切り替え、マイク監視の新規セッションなど現行コードが補正要求の状態を初期化する時点で `補正 +0 ms` に戻る。ボタンの押しすぎで要求が受理されないときは値を変更しない。

### 2.3 「一致度」

一致度はマイクと参照録音の特徴量の照合スコアであり、正しい認識の確率ではない。通常画面には照合の状態と短い候補表示を出す。スコア詳細と第二候補との差は詳細画面に残す。

## 3. 画面の縦方向構成

端末の上から次の順に配置する。

1. **トップ:** アプリ名。Androidのステータスバーと重ならない。
2. **音源:** ファイル名（長ければ省略）・解析状態・「変更」。
3. **同期:** 同期状態・大きい「同期を開始」／「認識を停止」ボタン。
4. **検知表示:** マイク入力と判定の現在状態。候補位置と一致度の簡易値があれば表示。
5. **同期オフセット:** `同期オフセット +0 ms` と1本のスライダー。同期コントロールの直下。
6. **詳細設定・診断:** 折りたたみ。判定閾値および必要な解析情報。
7. **下部プレーヤー（常に手前に見える領域）:** 細いシークバーと左右時刻 → `−100 | −50 | +50 | +100` → `補正 ±… ms` → 小さめの手動再生／一時停止。

上側の項目は端末高さが足りないときに縦スクロールし、下のプレーヤーは表示可能な範囲で常時利用できる。画面全体を大きなカードの集合にはしない。

### 3.1 Androidシステム領域との関係

- Android 15 / targetSdk 35以上で適用されるedge-to-edge表示を前提に、ステータスバー・ナビゲーションバー・画面切り欠きの`WindowInsets`を使ってコンテンツの安全な内側余白を確保する。
- 通常操作のタップ領域はシステムバーの領域に入れない。特に**再生／一時停止ボタンの下端が3ボタンナビゲーションバーと重ならない**こと。
- 下部プレーヤーにはシステムの下側余白に加えて8〜12 dpの余白を設ける。
- ジェスチャーナビゲーション・3ボタンナビゲーションの両方、縦画面・横画面で確認する。
- 画面切り欠きが左右へ移る場合も左右の余白を確保する。
- システムバーの高さは固定値で推定しない。実際に返されたinsetsを使う。

Android公式資料: https://developer.android.com/develop/ui/views/layout/edge-to-edge

### 3.2 画面の最小目標寸法

- 360 dp程度の狭い縦画面でも4つの時間補正ボタンを1列で表示する。各ボタンのタップ領域は原則44〜48 dp以上の高さを確保する。
- 補正ボタンの横幅は均等とし、短い数字だけを表示する。単位msは見出しで説明せず、補正の合計表示にのみ必ず含める。
- 下部プレーヤーの上に余白が余る場合も、不要なカードを増やして埋めない。

## 4. 同期コントロールと検知インジケーター

### 4.1 大きな同期ボタン

- 音源なし・参照解析中: `同期を開始`を無効化し、無効状態が一目で分かる色にする。
- 準備完了: `同期を開始`を主操作として表示。
- マイク入力開始後: 同じ位置で`認識を停止`に切り替え、強調を弱める。停止はマイクによる監視を止めるが、ローカル再生は継続する。
- 通常の`再生`／`一時停止`は下部に置く。同期ボタンと同じ重要度の色を使わない。

### 4.2 常時確認できる判定表示

同期コントロールの下に、下記のような**短い2行までのインジケーター**を設ける。

- 判定状態（例: `外部音声を待っています`、`照合中`、`一致度不足`、`候補が複数`、`位置を確認中`、`同期位置を確認`、`追跡中`）。
- 有効な候補がある場合の情報（例: `候補 04:23  ·  一致度 0.657`）。ない場合は空欄でもよい。
- 判定に時間的整合性が必要な2回確認の途中は`位置を確認中`として表示し、同期完了を先取りしない。
- 緑などの状態色は実際に同期位置が受理された場合に限る。候補表示だけで「同期完了」にしない。
- 信頼性の低い入力を含め、マイク監視が開始されていることは画面で確認できるようにする。

この領域に長い例外メッセージ、毎回の診断履歴、数秒ごとに増えるログを流し続けない。実際の解析状態や判定結果の値を表示し、架空の進捗率や固定のデモ値を使わない。

### 4.3 状態表示の対応表

| 入力・再生状態 | 主状態 | 判定表示 | 主ボタン |
| --- | --- | --- | --- |
| 音源未選択 | 音源を選択してください | 判定表示は非表示 | 同期を開始（無効） |
| 音源解析中 | 音源を準備中 | 解析中 | 同期を開始（無効） |
| 解析完了・マイク停止 | 同期待機中 | 外部音声の認識待ち | 同期を開始 |
| マイク開始・候補なし | 外部音声を認識中 | 外部音声を待っています | 認識を停止 |
| 候補が信頼できない | 外部音声を認識中 | 一致度不足／候補が複数など | 認識を停止 |
| 高信頼候補の1回目 | 外部音声を認識中 | 位置を確認中 | 認識を停止 |
| 2回一致・初回再生開始 | 同期して再生中 | 同期位置を確認 | 認識を停止 |
| 初回以降も照合継続 | 同期して再生中 | 追跡中／照合保留など | 認識を停止 |
| マイク停止・再生継続 | 再生中 | 判定は停止 | 同期を開始 |
| 読み込み・再生エラー | 読み込みに失敗 | 問題を短く表示 | 同期を開始（無効） |

## 5. 初回同期の設定と詳細診断

### 5.1 常時見える設定

「同期オフセット」だけを同期コントロールの下に常時表示する。通常のボタンとの識別を優先し、値は右側、スライダーはその下に細く置く。設定は既存のAndroidアプリ設定に保存する。

### 5.2 詳細設定・診断で見える項目

- **一致度閾値**: 初期値0.72、0.50〜0.95、0.01刻み。次候補との差の下限0.075と2回の確認は固定。
- **音源情報**: RIFF/WAVEの形式・チャンネル数など。読み込み警告は確認できる。
- **マイク入力レベル**: 数字は必要なときだけ確認する。入力が録音中かは通常画面にも伝える。
- **照合詳細**: 候補位置、スコア、候補差、判定の短い理由。
- **時刻差**: 外部音源の推定メディア位置とローカルプレーヤーのメディア位置の差。耳に届く物理的な遅延の測定値ではない。
- **再生状態とエラー**: 通常は短く表示し、異常時に原因を調べられる形にする。

上記は、意味の異なる値を単なる複数行ログとして並べない。小見出し、値、必要な場合だけ短い説明で構成する。アプリ内部の例外や長い診断文字列は必要なときに読み取れるようにする。

## 6. 見た目と操作感

- Android標準のコンポーネントに近い、落ち着いたダークテーマ。文字やボタンのコントラストを優先する。
- **大きな角丸カードとグラデーションを画面中で重ねない**。背景色・サーフェス色は2〜3階層程度に限定し、強調色は同期開始や現在の進行状態に用いる。
- 主要操作以外の情報は左寄せを基本とし、装飾目的の中央揃えや波形アニメーションは増やさない。
- 主要操作のラベルは実際の動作に対応させる。再生開始待ちを「同期完了」と表示しない。
- 同期オフセットのスライダーと再生中の補正ボタンは別領域とする。
- すでにアプリに組み込まれているヘッドホンと波形のアプリアイコンは維持する。デザイン変更で不要な追加アイコンを増やさない。

## 7. 実装を変更しない機能

- オフラインの同一録音照合とマイク使用許可。
- PCM16 WAVの独立した解析処理、MP3/M4Aの実験的解析処理。
- 初回自動シークは一度だけ。自動再生のフェードインは約600 ms。
- 再生中の `±50 / ±100 ms` 手動補正はプレーヤーの速度を0.95倍・1.05倍に変更する。繰り返しシークはしない。
- 一致度閾値と初回同期用オフセットの保存。
- Androidの画面回転に伴う状態維持。
- バックグラウンドでのマイク常時監視やBluetooth遅延の自動補正は対象外。

## 8. 受け入れ試験

1. **Android 15以降・3ボタンナビゲーション**: 通知バーの時刻・ナビゲーションバーのボタンと、アプリのタイトル・再生／一時停止・シークバーが重ならない。
2. **ジェスチャーナビゲーション**: ジェスチャー領域とプレーヤーのタップ領域が重ならない。
3. **縦横画面・狭い画面**: 4つの補正ボタンが表示できる。上部は必要に応じてスクロールし、プレーヤーの基本操作が使える。
4. **未選択状態**: 同期ボタンが有効に見えず、音源変更の操作が分かる。
5. **参照音源が解析済み**: 大きな同期開始ボタンを押せる。通常の手動再生ボタンと誤認しない。
6. **認識動作**: マイク開始後、候補がなくても現在の認識・判定状態が見える。候補があるときは時刻と一致度を簡潔に表示し、実際の評価状態と矛盾しない。
7. **同期オフセット**: 通常画面で−600〜＋600 msを調整でき、値が保存される。再生中の現在位置を動かさない。
8. **手動補正合計**: `+100 → +50 → −100` の操作で `補正 +50 ms` と表示し、速度補正の進行中も値が変わらない。
9. **詳細診断**: 閾値やファイル形式が表示され、エラー文は必要時に確認できる。展開しても再生とマイクを意図せず停止しない。
10. **回帰**: 解析・マイク開始・初回シーク・フェードイン・±50/100 msの速度補正・通常再生が以前と同じように動く。

自動テストで確認できない物理的な同期誤差と実際の聴き心地は、実機で別に評価する。
