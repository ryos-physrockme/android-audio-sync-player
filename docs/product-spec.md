# 動作仕様 — Android Audio Sync Player

更新日: 2026-11-09  
対象: Androidアプリ `0.2.11-dev`  
対象読者: 利用者、開発者、テスター

## 1. 目的と適用範囲

外部スピーカー・カラオケ機器など、スマートフォンから直接再生位置を制御できない機器の音をマイクから取得し、同一録音のローカルコピーをイヤホンに同期して再生するAndroidアプリ。

ここで「同一録音」とは、音声波形の時間的な対応が原則として保たれている録音を指す。別の伴奏・別編集・別演奏を同時に扱えるとは限らない。自動同期の性能は、室内の残響、周辺音、イヤホン、Android端末、エンコードの差などによる。

## 2. 利用手順

1. スマートフォンにあるローカル音源を「音声ファイルを選択」から指定する。
2. 音源の解析が完了して「解析完了」と表示されることを確認する。
3. イヤホンを接続する。「マイクを開始」を押して待機する（手動の「再生」は押さない）。
4. 別の機器から同じ録音を再生する。アプリが位置を認識した後、初回に1回だけ位置を合わせて再生を開始する。
5. 必要なら −100 ms / −50 ms / ＋50 ms / ＋100 ms で聴きながら調整する。再生中の調整は速度変更によって徐々に行われる。
6. 外部機器で位置を変更したときに同期し直すには、マイクをいったん停止し、再び開始する。

### 主要な操作

| 操作 | 期待する動作 |
| --- | --- |
| 音声ファイルを選択 | システムのファイル選択UIから音源を指定し、再生準備と参照解析を行う |
| 再生／一時停止 | ローカル再生を手動制御する。手動操作時はマイク同期を停止する |
| マイクを開始 | 再生位置照合を開始する。参照音源の解析が完了するまでは利用できない |
| マイクを停止 | マイク入力を停止する |
| 再生位置バー | 手動で再生位置を変更する。マイク同期は停止する |
| 再生開始の一致度閾値 | 照合に要求する一致度を変更する。低いほど開始しやすいが誤認識の危険が増える |
| 次の初回同期位置の補正 | 次に自動同期を開始する際の再生位置だけを調整する |
| ±50 ms / ±100 ms | 再生中にローカル音源の速度を短時間0.95倍／1.05倍へ変更する。シーク・一時停止を意図しない |

## 3. 自動同期の仕様

### 3.1 音声入力と特徴量

マイクはAndroid `AudioRecord` を使い、16 kHzモノラルPCMを入力する。参照録音は16 kHzモノラルへ変換される。長さ2,048サンプルのHann窓によるスペクトルから16帯域の正規化特徴量を計算し、512サンプル（32 ms）ごとに特徴量を生成する。

直近96フレーム（およそ3秒）と参照録音の特徴量を比較する。照合は約24フレーム（0.77秒）ごとに行う。

### 3.2 初回同期の許可条件

- 一致度の下限は0.50〜0.95の範囲で利用者が指定する（初期値0.72）。
- 離れた位置の第2候補とのスコア差は0.075以上とする。
- 十分な有効特徴量が必要で、静音や曖昧な候補では開始しない。
- 連続する2回の高信頼な候補時刻が時間的に整合する場合のみ、初回同期を受理する。

スコアは確率として較正された「成功確率」ではない。設定値を下げることは、認識の誤りを許容する危険も増やす。

### 3.3 再生開始と追跡

受理した外部音声の推定時刻、マイク取得時刻、現在時刻、手動の初回オフセットからローカル再生位置を算出し、初回に一度シークして再生する。再生開始時には約600 msのフェードインを行う。

その後はマイクによる照合を継続するが、自動シークや自動速度補正は行わない。自動補正を繰り返したときに再生位置が前後へ飛び続ける問題を避けるための仕様である。

画面に表示する時刻差は、推定した外部のメディア位置とローカルプレーヤーの報告位置との差であり、イヤホンから音が届いた瞬間の時間差ではない。

## 4. 手動時間補正の仕様

### 初回のイヤホン補正

保存する値の範囲は −600〜＋600 ms、10 ms刻み。正の値は次回の初回シーク位置を先へ進める。再生中に変更しても、その曲の再生位置は変更しない。

### 再生中の時間補正

再生中のボタンは `seekTo()` を使わず、プレーヤーの速度を一時的に変更する。

- 正の要求値: 1.05倍で再生し、ローカルを相対的に先行させる。
- 負の要求値: 0.95倍で再生し、ローカルを相対的に遅らせる。
- 50 msの補正にはおよそ1秒、100 msにはおよそ2秒がかかる。
- 複数の要求は合算し、反対方向の要求は未完了分を相殺できる。
- 未完了分は±500 msを上限とし、補正完了または停止時には再生速度を1.00倍へ戻す。

ボタンで指定する値は*要求した補正量*であり、イヤホンで得られた正確な補正結果を保証しない。コーデックや出力経路によって速度変更時の音質・バッファリングが異なる場合がある。

## 5. 設定とデータの保持

| 対象 | 現在の扱い |
| --- | --- |
| 再生開始の一致度閾値 | Androidのアプリ設定に保存 |
| 初回同期のオフセット | Androidのアプリ設定に保存 |
| 選択音源 | 画面回転や一部のActivity再作成時には復元を試みるが、通常のアプリ再起動時の「最近使用した音源」機能はない |
| 参照音源の特徴量 | 音源選択後に生成。永続キャッシュはなし |
| マイク録音 | 保存・ネット送信しない |
| 音源データ | 利用者が選択したローカルファイルを参照する。アプリに楽曲を同梱しない |

アプリをアンインストールした場合、保存した設定値は消える。

## 6. エラー時・画面状態の扱い

- 音源の再生準備と参照解析は別処理であり、片方が成功してももう片方が失敗する場合がある。
- 解析中、解析完了、再生エラー、マイク使用許可不足、照合保留、再生開始、再生中などを区別して表示する。
- WAVの一部には`data`チャンク長の宣言と実際のファイル末尾の不整合がある。完全なPCMフレームが十分読めれば警告付きで特徴量解析を完了する場合がある。
- AndroidのシステムUIで選択する音源は、ローカルでアクセス可能なファイルである必要がある。
- 画面がバックグラウンドへ移ると、マイク入力は停止する。

## 7. 対応形式・技術・検証状態

対応形式と実測上の限界は[機能一覧](feature-inventory.md)および[検証計画](test-plan.md)を参照。Androidの最小APIは26で、Media3 ExoPlayer、AudioRecord、MediaExtractor、MediaCodec、Kotlinなどを使用する。

現時点で、同一録音のWAVを使った実機での自動同期動作は確認されている。一方、音が耳に届く時刻差の系統的測定、Bluetooth遅延の自動補正、MP3・M4Aの実機音響同期精度、カラオケ伴奏と原曲の照合は未検証・未実装であり、性能を保証しない。
