# 画面デザイン方針 — Android Audio Sync Player

更新日: 2026-11-09  
対象実装: Androidアプリ `0.3.0-dev`

本書は、既存機能を壊さずに画面構成を整理するためのデザイン方針である。0.3.0-devで基本配置、ダークテーマ、詳細設定の折りたたみ、アプリアイコンを実装した。実機での視認性・操作性確認は継続中。

## 1. 利用環境

主な利用場所はカラオケ室や演奏練習の場所。利用者はイヤホンを付け、外部音源を聴きながら片手でスマートフォンを操作する。部屋が暗い場合もある。音楽の再生中に画面を長く見続けなくても使えることを優先する。

設計上の目標は「音源を選ぶ→待機→自動開始→耳で聴きながら補正」という一連の操作を少ない視線移動で済ませること。専門的な解析値は必要なときだけ確認できればよい。

## 2. 情報の優先順位

| 優先度 | 画面上の情報・操作 | 目的 |
| --- | --- | --- |
| 最優先 | 選択音源名、待機／認識／再生中の状態、マイク開始／停止 | アプリが何をしているか即座に分かる |
| 最優先 | 手動時間補正 `−100 / −50 / ＋50 / ＋100 ms` | 演奏中でも押しやすくする |
| 高 | ローカル音源の再生／停止、現在位置と全長 | 通常のプレーヤーとして操作できる |
| 中 | 次の初回同期のイヤホン時間補正 | 再同期時の位置調整に使う |
| 中 | 再生開始の一致度閾値 | 認識しづらい場所で調整する |
| 低 | 一致度、第2候補との差、推定時刻差、マイクレベル、音声ファイルヘッダー | 問題の調査・設定時に参照する |

## 3. 画面構成の候補

**メイン画面**

1. 上部: 選択した音源名と音源を変更する操作
2. 状態: 「音源を解析中」「外部音声を待機中」「再生中」「再認識待ち」「エラー」を、短い文言で表示
3. 再生: 再生位置とPlay/Pause
4. 手動微調整: `−100 ms  |  −50 ms  |  ＋50 ms  |  ＋100 ms`。左は遅らせる、右は進める
5. 主操作: マイク開始／停止

**詳細設定・診断（折りたたみ表示の候補）**

- 再生開始の一致度閾値（初期値0.72）
- 次の初回同期位置の補正（初期値0 ms）
- 推定した時刻差とその変化
- 一致度・候補間スコア差
- 音源の形式と解析警告
- マイク入力レベル

通常の歌唱練習中は、詳細情報が大きく画面を占めないことが望ましい。

## 4. ボタンと操作の設計

- 4つの時間補正ボタンは**位置と符号を常に固定**する。負の値はスマホ側を遅らせ、正の値は進める。
- 50 msと100 msは「要求する時間補正量」を表す。ボタンを押した瞬間に音源がジャンプするわけではない。
- 再生中は速度を0.95倍または1.05倍に変更して徐々に補正するため、「補正中」「補正完了」を分かりやすく表示する。
- マイク開始と通常の手動再生は役割が異なる。手動再生ではマイク同期が停止することをUIから判断できるようにする。
- 主要操作は片手でも押しやすい大きさを確保し、誤タップを減らす。狭い縦画面で4ボタンが収まらない場合は、十分なタップ領域を維持できる配置を優先する。
- フェードイン中や読み込み中は、操作可否を状態に応じて明示する。

## 5. 見た目の方針

- 暗めの室内で使いやすい明暗両テーマを検討する。配色はまだ確定させず、コントラストと視認性を優先する。
- フォントのサイズや太さで「今できること」と「技術的な情報」を明確に区別する。
- 装飾的な波形や無意味なアニメーションは必須ではない。操作を邪魔するほど情報量を増やさない。
- 日本語のボタン名は短く明確にする。UIに並ぶ時間の単位はmsとし、符号と向きが一致するようにする。
- 画面回転で音源が外れたり同期が中断しないよう、現在のライフサイクル処理を維持する。

## 6. 保存機能をどう扱うか

**現在実装されている保存**: 一致度閾値と次の初回同期の時間補正はアプリ設定に保存される。これを「プリセット管理」とは呼ばない。

**今後検討する最小機能**: 前回の音源を再選択できる「最近使用した音源」。Androidが既に付与したURIアクセス権限が有効な場合だけ復元を試み、ファイルが移動・削除された場合には再選択を求める。

**必要が出た場合の追加機能**: 有線イヤホン／特定のBluetooth機器など、出力機器別に初回時間補正を保存する。機器名と補正値を保存することと、実際の出力先を自動判定して適用することは別機能である。

曲別のプリセット管理、プリセットの任意命名や共有は現段階では実装しない。画面デザインに先立って複雑な設定管理UIを増やさないため。

## 6.5. 0.3.0-devで採用した配置

- 上に音源ファイル名、解析状態と変更ボタン。
- 中央に大きな「同期を開始」を置き、現在の状態は「同期待機中」「外部音声を認識中」「同期して再生中」などの短い表示で伝える。
- 下のプレーヤーは**シークバー → −100 / −50 / +50 / +100 → 要求補正合計 → 再生・一時停止**の順。プレーヤーは画面下部に固定する。
- 表示される「補正 +150 ms」などは、**ボタン操作で要求した正味の合計**。速度変更による補正の進捗に合わせて変化させない。
- 詳細設定・診断は初期状態で折りたたむ。説明書きや「左は遅らせる」など、自明な重複説明は通常画面に置かない。
- 端末用アダプティブアイコンを追加する。色は濃いネイビー系の背景と紫の主ボタンを基本とする。

## 7. デザイン変更の受け入れ基準

- 同一WAVの選択・解析・マイク待機・初回自動再生が従来通り動く。
- 100 msと50 msの時間補正、再生フェードイン、設定保存が壊れない。
- 画面回転、狭い縦画面、横画面で重要なボタンを見失わない。
- 解析値を隠してもエラー時には原因を確認できる。
- 画面を切り替えたりメニューを開くために、録音と再生が意図せず停止しない。
- アプリのバックグラウンド動作が未実装であることを、見た目で隠さない。

画面デザインの採用前には、実機での操作感を優先して比較する。詳細機能仕様は[動作仕様](product-spec.md)にまとめる。
